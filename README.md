# 色序 · Course Color Studio

从自己选择的颜色出发，生成、比较和微调最多 25 色的课程色板。目标是形成少量紧邻、能自然衔接的色系：已有颜色相隔较远时补足过渡，局部已经接近时探索相邻色系的变化，让整套配色保持共同风格。顶部统一设置全局规则与高级参数，左侧分析和编辑当前颜色，右侧管理色板、补全颜色和查看分布。页面右上角的“文档”进入 [文档目录](docs/index.html)，集中阅读使用指南、算法、配色分析、研究来源和验证记录。

工作台每次从空白开始，只维护一份 0–25 色的当前色板，不再区分主色列表和生成结果。颜色只保留在当前页面会话中，不写入浏览器缓存，也不会自动恢复；需要归档时可命名并导出 JSON。计算与导出均在浏览器完成，无需后端服务。

> 初始文字对比阈值为 **1.65:1**，用于浅色课程配色探索，**不满足 WCAG AA 常规正文的 4.5:1 要求**。需要正文 AA 时点击滑杆上的 **4.5** 刻度，并结合实际文字颜色、字号和使用背景检查。“当前规则通过”只表示色板通过所设参数。

## 启动与验证

项目使用 React、TypeScript 与 Vite，通过 npm 安装和运行，无需 Yarn。需要 Node.js 20.x（至少 `20.19`），或 `22.12` 及以上版本。首次进入本目录后执行：

```powershell
npm install
npm run dev
```

之后直接执行 `npm run dev` 即可启动。打开终端显示的地址，通常为 `http://127.0.0.1:5173`。需要严格按 `package-lock.json` 复现依赖时使用 `npm ci`。构建、测试和预览：

```powershell
npm test
npm run build
npm run preview
```

测试覆盖生成、局部替换、色码转换、约束审计和近邻风格回归。`build` 检查 TypeScript、生成 `dist/` 并复制文档；静态部署发布完整 `dist/`，其中包含可直接访问的 `docs/index.html`。图标使用 [Lucide](https://lucide.dev/) 的 React 组件，许可说明见 [研究来源](docs/SOURCES.md)。

`src/main.tsx` 挂载 React 应用，`src/App.tsx` 管理工作台状态和计算任务，`src/components/` 拆分全局规则、颜色编辑、当前色板分析与固定示例预览。原有色彩数学、约束审计、采样和排序模块继续作为独立算法层，由 Web Worker 执行生成。

## 从主色到色板

1. 点击右侧色板末尾的虚线加号卡，添加一个颜色，并在左侧分析与编辑。加号卡与普通色块尺寸一致，满 25 色后自动消失。空色板的首色在 sRGB 与硬彩度区间内抽取；已有颜色时沿当前分布继续生长。要自定颜色，新增后在左侧输入 HEX；也可打开顶部风格预设，在预览中使用其代表主色载入当前色板。
2. 在地图上点击或拖动，粗调色相和彩度；悬停查看候选的 HEX、OKLCh、文字对比和当前规则诊断。下方按明度 L、色相 h、彩度 C 的顺序微调，也可直接输入 HEX。
3. 在页面顶部设定文字颜色、最低文字对比度和种子。高级选项与自定义色彩范围始终展开；自动范围从起点建立，在后续生长中保持稳定，手动加色、编辑或删除后重新建立。直接修改任一边界即可固定范围，重置范围即可恢复自动范围。
4. 点击色板标题栏中的魔法棒“生成”按钮，保留当前所有颜色的 HEX，按同一取点流程依次补到 25 色，成功后自动整理显示顺序。选中哪些颜色不改变补全输入；要替换选中色可点击“随机”，也可先删除，再继续生成。满 25 色时无需继续补全。最小色差用于避免颜色近乎重合，不以把色点尽可能拉开为目标。计算在 Web Worker 中运行，可取消；失败、部分结果或取消均保留当前色板。

新增一色、补全和随机替换共享逐色取点流程。每次新增都根据当时的颜色分布决定补过渡或探索相邻方向，记录生成关系；自动排序只改变展示，不把排在最前面的颜色当作最早出生的颜色。相同种子、规则、范围和生成关系下，逐次新增与直接补全使用相同的后续序列；点击“随机”会更换种子。空色板也可直接尝试生成，若新首色不满足后续规则，本次操作会停止并保留空色板。

首色不使用此前自定义域的明度、彩度、色相范围或文字对比过滤，但始终满足全局彩度上下界，便于重新寻找起点；其真实审计结果仍会显示。后续新增和补全必须保留现存颜色并满足当前规则：若首色违反文字要求或固定范围，流程会明确停止，需先编辑颜色或调整规则，不会悄悄重抽首色。

编辑颜色会直接更新当前色板，修改规则则保留现有颜色并重新审计。继续生成必须保留全部现存颜色，因此固定颜色本身的冲突需要先通过编辑、删除或调整规则解决。

## 风格预设与固定示例

“水雾森林”和“暮山陶土”各保留 25 个原始 HEX，是固定、只读的内置示例，工作台不会默认载入任何一套。点击顶部任一风格按钮先打开“查看原色板与分布”预览，不改变工作台。

预览头部的“使用主色”位于关闭按钮左侧，点击后才把该示例的代表主色载入当前色板，并应用底色规则与生成范围；**保留用户当前的文字颜色和最低文字对比度**，不会为了套用示例而降低文字要求。随后编辑的是工作台，示例原件保持不变。

原色卡始终可以点击查看，并在两张分布图中定位；旁边独立的加号才将该颜色加入当前色板，逐个取色不会覆盖当前规则。当前色板满 25 色时只禁用取色加号，原色查看仍可使用。完整原色表不参与候选采样；生成只使用当前色板与规则。页面不设参考方案区，也不提供 JSON 导入或保存为参考方案。

## 查看整套配色的分布

当前色板下方的“颜色之间的衔接”直接展开两张分布图、颜色详情、整套统计、约束检查与当前生成规则和边界，无需点击“查看空间分布”或打开子页面。固定示例仍在各自的原色板预览中查看分布。

a/b 图观察色相方向与离灰心的距离；h/L 图观察色相与明度层次，在最大色相空隙处展开，因此暮山陶土跨过 0° 的暖色不会被拆到两端。上方色板选中的颜色会同时标记在两张图中，详情对应当前左侧编辑对象，显示 HEX、L/h/C、文字对比与最近邻色差。悬停或用键盘聚焦其他色点可临时比较；点击色点或按 Enter / 空格会定位左侧编辑对象，不改变用于删除的多选集合。排序或删除后，图中标记和详情随颜色对应关系更新。

短连线是完整三维 OKLab 距离的最小生成树（MST）在两张图上的投影，与原输入顺序无关。二维画面上的线长不能直接当作真实色差。统计使用统一的数值与标签样式，展示最近邻色差的中位数 / P90、连接整套色板的最大步长，以及全部颜色对的色差与底色对比分位数：最近邻看局部密度，MST 看整套如何衔接，全对分布看整体跨度。其下的最小色差、最大底色对比和最低文字对比用于检查当前规则，文字对比始终使用顶部设置的文字颜色。

空色板不显示分析；只有一个颜色时仍显示该色的坐标和文字对比，最近邻、连接步长及颜色对统计显示“—”，避免把不存在的颜色对当作实测结果。

| 原始 25 色的统计 | 水雾森林 | 暮山陶土 |
| --- | ---: | ---: |
| 最近邻 ΔE：中位数 / P90 | 3.133 / 3.907 | 4.228 / 5.492 |
| MST 连边 ΔE：中位数 / P90 | 3.337 / 4.153 | 4.317 / 5.665 |
| 全 300 对 ΔE：中位数 | 10.270 | 11.724 |
| 全 300 对底色对比：中位数 / P90 | 1.394 / 2.156 | 1.475 / 2.510 |

这些分布说明每色都有近邻，整套可通过较小步长衔接；不代表任意两种颜色都很近。森林保留雾绿—蓝绿—雾蓝的变化，陶土保留灰蓝—藕紫—玫瑰—陶土的过渡。详细分析、精确原色和可复算数据见 [配色分布研究](docs/PALETTE_STUDY.md)，运行 `node scripts/analyze-palettes.mjs` 可重建分析数据与图。这里的统计针对原始示例，不是生成结果的成绩或通用审美标准。

## 读懂颜色与地图

HEX 是唯一的颜色编码输入，接受三位或六位写法；RGB 与 HEX 表示同一组 sRGB 通道，因此不再提供重复的 RGB 输入。

| 参数 | 影响 | 如何调整 |
| --- | --- | --- |
| 明度 L | 控制感知上的深浅；不是 WCAG 相对亮度 Y。 | 在下方调整，地图会切换到新的明度截面。固定白字时，较深的底色通常更容易满足文字对比。 |
| 色相 h | 控制红、黄、青、蓝等颜色方向，是循环角度。 | 围绕地图中心改变方向；近中性灰时，色相变化的视觉影响很小。 |
| 彩度 C | 控制离中性灰的距离；越大通常越鲜明。 | 在图中向外增加、向内减小。实际可用上限随色相和明度变化。 |

方向候选提供“更明亮 / 更沉稳”“更柔和 / 更鲜明”和色相 `±15°`，每次应用一个小变化，并说明变化对当前颜色和规则的影响。明度步长为 `0.04`、彩度步长为 `0.015`；它们用于探索方向，仍需通过整套色板检查。

地图展示**当前 L 的 OKLCh 二维切片**，支持缩放、复位和展开。高分辨率绘制与连续边界减少锯齿；它无法在一张切片中展示所有明度。

- **sRGB 边界**表示可输出为 HEX 的范围。边界内都可以编辑，暂时违反生成规则的颜色仍可保留并显示原因。
- **Display P3 参考边界**展示更宽色域在相同明度下的范围。超出 sRGB 的部分以灰色示意，不模拟 P3 色彩，也不能作为当前输出。
- **生成范围**来自当前随色板更新或已固定的自定义边界，与设备色域分开显示；只有当前明度在域内时才显示对应截面。
- **斜线提示**是硬约束未通过区域的采样示意，悬停卡使用实际量化 HEX 做精确检查。图中不存在固定 `C = 0.1` 的额外点选门槛。

拖动时预览，松开后应用；超出 sRGB 时不修改颜色。地图获得焦点后，可用左右键调色相、上下键调彩度，Shift 增大步幅，Enter 应用，Escape 取消预览。

## 全局规则与高级参数

全局规则位于顶部，高级选项直接展开。文字对比使用滑杆与数值输入，并在滑杆上提供可点击的 `1.65` 和 `4.5` 刻度。两者都设置**最低文字对比度**，不是上限；首色自由抽取后会显示实际检查结果，后续新增、补全与保留固定颜色的替换都要求达到该值。

初始条件为最小色差 `1.4`、底色最大对比 `3`、文字最小对比 `1.65`、硬彩度范围 `0.03–0.11`。水雾森林的底色上限为 `3`；暮山陶土的原表最大底色对比约为 `3.417`，其风格预设明确使用 `3.5`。显式使用风格预设只更新代表主色及相应底色条件与范围，文字色和文字阈值保持当前值。

| 参数 | 初始值 | 检查对象 |
| --- | --- | --- |
| 最小色差 `minDeltaE` | `1.4` | 所有颜色对的 `100 × OKLab 欧氏距离` 下界；25 色共 300 对。 |
| 底色最大对比 `maxBackgroundContrast` | `3` | 任意两种底色的 WCAG 比值上界，限制全套深浅跨度。 |
| 文字色 `textColor` | `#FFFFFF` | 每个课程色上使用的固定文字颜色。 |
| 文字最小对比 `minTextContrast` | `1.65` | 固定文字与每一种底色的 WCAG 比值下界。 |
| 彩度硬下限 `minChroma` | `0.03` | 远离黑白灰轴，首色与后续生成色均检查。 |
| 彩度硬上限 `maxChroma` | `0.11` | 限制鲜艳程度，首色与后续生成色均检查。 |
| 范围状态 `domainMode` | `auto` | 根据起点建立生长范围；修改边界后转为 `manual` 固定范围。此字段保留在 JSON 中，界面无需切换模式。 |

彩度 C 是 OKLab 的 a/b 平面上离中性轴的距离：`C = sqrt(a² + b²)`，C 趋近 0 即接近黑白灰。默认硬下限 `0.03` 排除过灰区域，上限 `0.11` 限制鲜艳程度；两端在同一组输入中调节。两套原例的最低 C 分别约为 `0.0456`、`0.0305`，因此默认区间不改变原色。下限可设为 0 以允许中性色，上下界不得倒置。地图用同心内外圈标出该硬区间，与设备色域和自定义生成域分别显示。

自动范围由起点建立：单色的 L 余量为 `0.12`，多色为 `0.04`，C 余量为 `0.025`，色相余量为 `12°`。单色或色相弧很窄时，范围向色相中心两侧各扩展 `47°`，提供三个相邻探索方向。L 裁到 `[0,1]`、C 裁到 `[0,0.4]`，可用颜色仍受彩度硬上下界约束。同次生长保持范围稳定，手动加色、编辑或删除后重建；只有显示排序改变时不重建。具体取点与边界见 [算法说明](docs/ALGORITHM.md)。

单主色的彩度评分允许在起点附近小幅向内、向外变化，越出柔性范围后才增加偏离代价，避免色点全部挤在色相 / 彩度图的同一半径上。硬彩度上下界仍然有效；若自行把彩度域收得很窄，输出也会相应变窄。

自定义色彩范围与编辑器同样按 **L → h → C** 排列。直接修改任一边界就固定整组区间，之后编辑颜色不再改变它；重置范围即可恢复自动范围。色相沿递增方向取弧，`330 → 45` 跨过 0°，`0 → 360` 表示完整圆周；L、C 下限不得大于上限。后续取点使用生成范围与硬约束的交集，扩大 C 区间不会取消 `[minChroma,maxChroma]`，自动范围也不会替用户降低文字对比或色差要求。

色差参数用于控制色点密度，不能当作 CIEDE2000 阈值，也不能保证所有课程在各种屏幕和字号下都能仅凭颜色辨认。仍应保留课程名称等信息。

## 选择、删除与排序

单击色块即可切换选中或取消，可选任意多个；Shift 点击连选，也可全选。点击色码进入左侧编辑器，仅改变编辑对象，不改变选中集合。没有单选 / 多选模式开关。已选数量、全选、清空、删除、排序、随机和生成集中在色板标题栏，按选择、整理与生成分组。

“清空”只取消选择，不删除颜色；红色“删除”会移除全部选中颜色。删除后点击“生成”，将剩余所有颜色作为固定输入补到 25 色；未删除颜色的 HEX 保持不变，但成功后会自动排序。

“随机”替换选中的颜色。部分选择时保留未选 HEX 与槽位，冻结当前范围依次生成替换色，再放回原槽位；全选时从空起点重新生长到原来的颜色数量，包括只有一个颜色且选中的情况。全选会放弃旧生长范围、恢复自动范围，让新首色重开风格，仍保留全部全局硬规则；它不会把旧色板当作固定集合或要求生成 25 色。完整补到 25 色由“生成”负责。

排序只调整顺序，既不改颜色，也不能修复约束冲突。每次成功生成会自动排序；当前顺序已经符合排序结果时，按钮显示灰色对号和“已排序”，否则可以点击排序。排序会跟随颜色映射选中状态和编辑对象，不把它们误移到原下标对应的其他颜色。

## JSON 与图片导出

- **JSON**保留保存时填写的名称、当前颜色、规则、实际有效域、`domainMode`、种子和 `growth` 生成关系（出生顺序、父节点与取点策略等），并附按当前 HEX 计算的审计指标，供归档和外部处理。页面只提供导出，不提供文件导入。
- **SVG**保留独立色块和文字，适合进一步编辑。
- **PNG**适合直接查看和分享。

色板卡片不显示方案名称输入行；选择导出格式后，在保存对话框中命名。JSON、SVG、PNG 都允许导出 1–25 色，空色板不可导出；图片保留当前文字颜色。输出始终是不透明八位 sRGB；P3 参考边界不改变导出空间。允许导出仍有警告的探索方案，应同时查看实际审计结果。

关闭或刷新页面会结束当前会话。页面不读取旧版自动暂存数据，没有本地自动恢复或云同步。

## 无法补全时

先看诊断指出的固定颜色和具体条件。现存颜色已经太接近、超出自定义范围或不满足文字要求时，增加采样无法在保留原色的同时消除冲突。可以在左侧修改颜色、删除冲突颜色，或有意识地调整顶部规则，再次生成。

固定集合有效但搜索未完成时，可扩大域、降低色差要求、减少固定颜色或换种子尝试。有限搜索失败只说明本次没有找到完整结果，不证明数学上无解。白字 `4.5:1` 要求底色相对亮度不大于约 `0.18333`；保留大量浅色时，需要同时考虑深色文字和实际用途。

完整阅读入口见 [文档目录](docs/index.html)。算法、架构及固定示例的历史证据见 [ALGORITHM.md](docs/ALGORITHM.md)；两套原始配色的完整分布证据见 [PALETTE_STUDY.md](docs/PALETTE_STUDY.md)；色彩数学、标准与图标许可见 [SOURCES.md](docs/SOURCES.md)。
