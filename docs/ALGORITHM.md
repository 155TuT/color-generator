# 色板生成算法

本项目在已有颜色附近逐色探索，使配色包含少量相邻色系和连续过渡。颜色距离较远时优先补中间，局部接近时寻找邻近方向的变化。色差下限负责避免重复，最远距离不作为越大越好的目标。

工作台通过 `runPaletteOperation` 调用 `growPalette`，在 Web Worker 中完成计算。新增、补全和随机替换共享顺序生长流程；编辑和排序在主线程处理。

## 项目状态与操作

`Project` 保存以下数据：

| 字段 | 用途 |
| --- | --- |
| `version` | JSON 结构版本，当前为 `1`。 |
| `name` | 保存时填写的名称。 |
| `colors` | 当前 0–25 个 HEX，按显示顺序排列。 |
| `constraints` | 色差、底色对比、文字颜色与对比、硬彩度上下界。 |
| `domain`、`domainMode` | L/C/h 范围及自动或固定状态。 |
| `seed` | 确定性采样种子，由内部维护。 |
| `growth` | 颜色的出生顺序、父节点、策略、参考方向和生长范围。 |

`growth.nodes` 的节点包含 `id`、`hex`、`birthOrder`、`parentId`、`strategy`、`distance`、`branch`。策略为手动固定 `fixed`、随机首色 `seed`、补过渡 `bridge` 或相邻探索 `explore`。显示排序不改变出生顺序。

`synchronizeGrowth` 通过同 HEX 的节点队列对应现有颜色，使排序和重复的手动颜色不混淆生成关系。新手动色获得固定节点；删除父节点后，存活子节点解除该父引用。手动修改或删除会重建风格参考，单纯排序不会。`snapshotProject` 克隆完整状态并写入当前有效范围，作为计算与导出的输入。

| 操作 | 固定输入 | 目标与结果 |
| --- | --- | --- |
| `add` | 当前全部颜色 | 增加一色，追加到末尾。 |
| `complete` | 当前全部颜色 | 顺序补到 25 色，成功后由工作台排序。 |
| 部分 `randomize` | 未选颜色 | 冻结当前范围及风格参考，逐色替换选中位置，数量与未选槽位不变。 |
| 全部 `randomize` | 空集合 | 从首色重新生长至原数量；自动范围重新建立，手动范围保留。 |

随机替换更换内部种子，并排除替换前的全部 HEX。操作只在完整成功时应用；有限搜索失败、Worker 错误或取消均保留操作前的色板。失败附带的中间结果仅用于说明停止位置，不会写入工作台。

## 色彩数学

实际存储与输出为不透明六位 sRGB HEX（每通道 8 位）。输入接受三位和六位 HEX，统一为大写六位。浮点候选先转换、量化为 HEX，再从该 HEX 重算全部指标。

设八位通道为 `c8`，归一化值为 `c = c8 / 255`，线性通道为：

```text
c_linear = c / 12.92                       c ≤ 0.04045
c_linear = ((c + 0.055) / 1.055)^2.4       c > 0.04045
```

`color.ts` 使用 OKLab 转换矩阵，从线性 sRGB 得到 `(L,a,b)`。OKLCh 是其柱坐标表达：

```text
C = sqrt(a² + b²)
h = atan2(b, a)，换算为角度并归一化到 [0°, 360°)
a = C cos(h)
b = C sin(h)
ΔE = 100 × sqrt((L₁−L₂)² + (a₁−a₂)² + (b₁−b₂)²)
```

L 表示感知明度，C 表示离中性轴的距离，h 表示色相方向。接近中性轴 `C < 10⁻⁶` 时色相不稳定，不据其方向限制生成域。这里的色差是放大 100 倍的 OKLab 欧氏距离，不是 CIEDE2000，也没有二者的固定换算比例。

WCAG 相对亮度与对比为：

```text
Y = 0.2126 R_linear + 0.7152 G_linear + 0.0722 B_linear
contrast = (max(Y₁,Y₂) + 0.05) / (min(Y₁,Y₂) + 0.05)
```

OKLab 的 L 与相对亮度 Y 含义不同。对比判定使用未舍入值，界面显示位数不影响判定。

反向转换先检查线性 sRGB 通道是否处于 `[0,1]`，仅容许转换误差 `2 × 10⁻⁷`，再编码并四舍五入到每通道 8 位。超出色域的候选直接拒绝，不通过裁剪通道伪装成目标色。

## 硬规则

每个生成颜色及所有涉及它的颜色对都必须满足：

| 条件 | 默认值或定义 |
| --- | --- |
| 有效、不重复的 sRGB HEX | 色码必须可解析，任意两色不能完全相同。 |
| 生成范围 | 实际 L/C/h 位于当前有效域内。 |
| 最小色差 | 任意两色的 ΔE ≥ `1.4`。 |
| 最大底色对比 | 任意两种底色的比值 ≤ `3`。 |
| 最低文字对比 | 固定文字 `#FFFFFF` 与每个底色的比值 ≥ `1.8`。 |
| 硬彩度 | `0.03 ≤ C ≤ 0.11`。 |

`minChroma` 缺省时按 0 解释；新建项目显式使用 0.03。L 范围限于 `[0,1]`，C 范围限于 `[0,0.4]`，色相边界限于 `[0,360]`。L/C 区间不可倒置，色相按递增圆弧解释：`[330,45]` 跨过零点，`[0,360]` 为整圆。

`validatePalette` 检查参数、单色条件与所有颜色对，并计算最小色差、最大底色对比、最低文字对比等当前指标。25 色有 300 对。比较误差容限为 `10⁻¹⁰`，用于浮点计算，不放宽用户设定。

手动编辑可保留暂时冲突的颜色，便于逐项修改；生成前固定集合必须符合全部规则。编辑器的 `createCandidateChecker` 只用候选自身及相关颜色对决定 `hardAllowed`，同时返回整套规则状态。因此修复一个颜色不会被另两个颜色之间的旧冲突阻断。批量地图绘制复用固定集合的指标，单个候选的追加计算量为 O(n)。

默认文字比值 1.8 是项目的探索参数，低于 WCAG AA 常规正文要求的 4.5。底色之间的比值上限用于控制风格，不能解释成文字无障碍规则。

## 自动范围与风格参考

空白自动项目从 L `[0.50,0.82]`、C 的硬区间、完整色相圆开始。首色建立风格范围后，该次生长保持范围不变。手动边界直接覆盖自动范围。

自动范围由现有起点的最小包络加余量组成：

- 单起点的 L 余量为 0.12，多起点为 0.04，裁到 `[0,1]`。
- C 两端各加 0.025，裁到 `[0,0.4]`，实际生成仍与硬彩度区间取交集。
- 色相在最大的圆周空隙处切开，两端各加 12°。
- 单起点或原色相弧小于 45° 时，范围改为中心两侧各 47°，参考方向设为中心及其 `±35°`。
- 更宽的多色输入，参考方向取已有最短色相路径采样的 20%、50%、80% 分位位置。

自动随机首色及其后续生长的明度范围与 `[0.50,0.82]` 取交集。删除生成色后也保留仍包含存活颜色的原明度边界，防止连续删除与补色逐渐放大明暗跨度。手动固定色、导入颜色和显式自定义范围保留自身明暗设定，不改写已有 HEX。

`makeStyleModel` 使用完整 OKLab 距离构建最小生成树。每条边按不大于约 ΔE 4.5 的分段数插入参考点，L 和 C 线性插值，h 沿最短圆弧插值；中性端点借用另一端色相。这使过渡沿相邻色相变化，避免直接穿过 a/b 平面的灰心。

参考点只参与软评分与方向比例，不能绕过硬规则。多色起点各方向的参考路径占比用于分配探索权重，少量端点色不会自动要求占据三分之一色板。单起点使用均衡的方向权重。

## 首色采样

种子经过 32 位哈希和确定性伪随机序列产生偏移量。三个轴使用基数为 2、3、5 的 Halton 序列，加偏移后对 1 取模：

```text
L = Lmin + uL × (Lmax − Lmin)
C = sqrt(Cmin² + uC × (Cmax² − Cmin²))
h = wrap(hstart + uh × hueSpan)
```

C 使用平方根映射，使 a/b 平面环形面积均匀采样。首色的 C 区间先与硬彩度范围相交。最多尝试 16000 个点，返回第一个经过实际 HEX 的 sRGB、范围、彩度与文字对比判定的颜色；找不到时停止，不降低阈值。

## 后续颜色的选择

每一步根据当前节点集合重建近邻关系，并从固定风格参考中计算候选评分。每步使用三轮各 2048 点的 Halton 采样；种子键包含项目种子、下一出生序号与轮次，不含本次目标数量。因此新增一步与补全多步共享同一序列。

候选先量化为 HEX、去重，再检查自身和全部已有颜色。三轮共享候选去重集合，最后在通过条件的点中选择最低分。

### 局部步长

设当前域与硬彩度交集为 `[C低,C高]`，色相跨度单位为度：

```text
V = (Lmax − Lmin) × (C高² − C低²) × hueSpan × π / 360
s = max(2.8, min(4.4, 70 × cbrt(V / 25)), 1.6 × minDeltaE)
```

`s` 是局部距离偏好，不要求填满整个体积，也不替代硬色差下限。

### 远处补过渡

取当前最小生成树的最长连边，长度为 `D`。当：

```text
D > max(5.2, 1.6s, 3.2 × minDeltaE)
```

本步进入补过渡分支。目标为该边两端在 OKLCh 中的中点，色相沿最短弧插值。候选到最近已有色的距离 `d` 不得超过 `max(6,0.6D)`，评分为：

```text
2 × ΔE(候选,目标) + 0.4 × 彩度偏离 + 0.15 × |d − D/2|
```

该策略优先补当前最大的连接缺口，而非机械地按颜色数量缩减允许距离。

### 近处探索相邻方向

不满足补过渡条件时，要求 `d ≤ max(5.8,1.8s)`，使用：

```text
score = 1.6 × |d − s|
      + 0.25 × 当前方向颜色数 / (该方向参考比例 × 方向总数)
      + 0.8 × 彩度偏离
      + 0.014 × 色相偏离
```

候选归属最近的参考色相方向。色相偏离为：

```text
max(0, |最短色相差(方向中心,候选)| − 18°)
```

方向中心 `±18°` 内不扣偏离分，相邻软区间可以连接。方向用于引导变化，不要求生成几个彼此隔离的色组。

### 彩度变化

多起点的候选取最近参考点彩度 `C参考`，偏离代价为：

```text
100 × (|C − C参考| + 0.25 × max(0,C参考 − C))
```

向灰侧略多计代价，但增加彩度也有代价，避免一味追求鲜艳。

单起点彩度 `C₀` 代表一个柔性范围。半宽为 `w = min(0.018,s/200)`，将 `[C₀−w,C₀+w]` 与生成域和硬彩度相交得到 `[C低,C高]`。区间内不扣彩度偏离分，区间外代价为：

```text
100 × (max(0,C低 − C,C − C高) + 0.25 × max(0,C低 − C))
```

这允许色点向内和向外变化，避免唯一参考彩度变成固定半径。带宽由起点和固定域确定，不随当前数量缩小；显式指定很窄的彩度范围时，生成分布仍会服从该范围。

最低分候选的最近已有颜色成为父节点，记录出生序号、策略、父子色差和方向。最终整套 HEX 再通过硬规则后返回成功。所有阈值、权重和预算均为项目的启发式参数，不能保证任意输入都生成恰好两到三个色系或补满 25 色；有限搜索未完成也不证明连续空间里不存在解。

## 分布计算与排序

`analyzePalette` 为每个颜色计算最近邻距离，枚举全部颜色对，并用 Prim 算法构建完整三维 OKLab 距离的最小生成树。分位数使用 R-7 线性插值：对升序数组，位置为 `(n−1)p`，在相邻元素间插值。

| 统计 | 解释 |
| --- | --- |
| 最近邻距离中位数 / P90 | 局部色点密度与较稀疏颜色的邻接距离。 |
| MST 最大连边 | 将整套色板连通时需要跨过的最大一步。 |
| 全对色差中位数 / P90 | 整体颜色跨度。 |
| 全对底色对比中位数 / P90 | 多数组合的明暗差异。 |
| 最小色差、最大底色对比、最低文字对比 | 对应硬规则的极端值。 |

最近邻很小仍可能存在几个分离色组，因此还需结合 MST 和实际色块观察衔接。a/b 图展示色相与彩度，h/L 图在最大色相空隙处展开，跨零色系能连续呈现。两图连线是同一三维 MST 的投影，不代表二维线长等于色差。

排序至少三色时执行：在最大色相空隙处切开，覆盖弧小于 35° 分一组，小于 85° 分两组，其余分三组，以内部最大的色相间隙划分组界。每组从最暗色开始，依次取 OKLab 最近的剩余点；与前一组衔接时比较正反两端，选择较短跳跃。少于三色保留原序。

排序只置换 HEX，不改变颜色对指标或生成关系；它是浏览排列的启发式，不保证全局最短路径或整体明度单调。

## 色彩地图与编辑

地图是当前 L 的 a/b 截面：右侧为 h = 0°，逆时针转动改变色相，半径表示彩度。可见范围随当前 Display P3 截面调整。sRGB 与 Display P3 边界分别转换到其线性通道，沿色相方向二分求最大合法半径；图中额外显示生成域及硬彩度内外圈。

Display P3 仅作范围参照，超出 sRGB 的区域以灰色表示。斜线是硬规则的采样提示，悬停详情按实际 HEX 计算。生成域之外或暂不满足对比的 sRGB 颜色仍可手动应用，以支持逐项调整；超出 sRGB 的点不能应用。

拖动只预览，松开才提交；连续拖动合并为一条历史。方向候选在 L、C、h 上分别使用 `±0.04`、`±0.015`、`±15°`，转换为实际 HEX 后呈现影响。

## 文件与会话运行

`project-io.ts` 按允许字段重建项目，接受最多 1 MB 的 `version: 1` JSON。颜色最多 25 个；数值必须有限且位于结构允许范围，生成节点数量及 HEX 多重集合必须与色板一致。父节点必须存在且出生更早，节点 ID 与出生序号对应。缺少 `growth` 的文件以所有导入色作为固定输入，并保留文件记录的自动有效域。导入不信任预先附带的统计，工作台始终重算当前指标。

导出 JSON 包含项目快照、有效域、生成关系、导出时间、算法标识及当前指标。SVG 和 PNG 使用当前文字颜色和色板顺序，按每行五色排版；文件名过滤非法路径字符和保留名。保存名称在写入成功后更新。

目录保存由 `file-save.ts` 使用 File System Access API 完成：只查找目标文件，缺失时创建，存在时完整替换。写入流使用 `keepExistingData: false`，等待写入和关闭后返回；失败则尝试中止流。目录句柄只在页面内存持有，不进入 JSON 或历史。浏览器不支持目录选择时仍可通过普通下载保存。

`history.ts` 最多保存 100 步项目编辑。连续手势共用历史分组，输入框保留原生撤销；新编辑清空重做分支。撤销和重做会取消正在运行的 Worker，恢复项目及对应的编辑和选择位置。页面刷新后项目、历史与目录句柄均不自动恢复。

文档目录由 `src/docs.ts` 从固定允许列表读取 Markdown，通过 Marked 解析与 DOMPurify 清理后呈现。构建把正文、示例 JSON 和依赖许可一同发布，不依赖外部 CDN。
